# 设备与升级验证

## 自动检查范围

`Android checks` 使用 API 26（x86）、34 和 36（x86_64）Google APIs 模拟器。
每个版本执行同一套 instrumentation 测试，包括前台服务生命周期、后台结果保存、
启动与运行中的模拟位置授权、暂停后撤权、路线迁移、文件替换和大字体布局。
结果见每次 Actions 的 `android-device-reports-api-*` 产物；配置测试矩阵不等于所有真机均已验证。

主机单元测试覆盖几何计算、KML 解析、路线仓库、配速、运行状态机及旧版路线标识迁移。
布局测试检查 320 / 375 / 640 dp 宽度和 1 倍 / 2 倍字体下的文字完整性、触控高度和文字对比度，
它不能替代真实显示效果、TalkBack 和厂商系统上的操作验证。
设备报告中另附 375 dp 常规字体与 320 dp 两倍字体的完整布局预览图，便于人工检查；
图片来自 Android View 实际排版与绘制，使用界面默认示例文字，不代表第三方应用效果。

## 目标设备验收

记录手机或模拟器型号、Android 版本、APK 版本及证书指纹，再执行：

| 场景 | 操作 | 预期 |
|---|---|---|
| 运行中撤权 | 开始后切换模拟定位应用，或将本应用的模拟位置 AppOp 设为 ignore | 进入失败状态，停止累计里程，保存失败原因 |
| 暂停中撤权 | 暂停后撤权，再尝试恢复 | 任务结束，不能继续推进；重新授权后需手动开始 |
| 锁屏与后台 | 运行至少 60 分钟，其间锁屏、回桌面、重新打开页面 | 任务保持单一运行状态，进度无重复累计，通知操作可用 |
| 结束清理 | 分别完成、停止和制造定位错误 | 通知移除，定位测试提供程序按系统允许的权限清理，唤醒锁释放，最近结果可读 |
| 小屏与大字体 | 320 dp 宽度、最大系统字体、横竖屏切换 | 输入框、控制按钮与数据可读可操作；必要时滚动，无系统栏遮挡 |
| 键盘与辅助功能 | 编辑参数、开启 TalkBack、关闭系统动画 | 焦点与标签合理，软键盘不遮挡当前操作，功能不依赖动画 |
| 进程终止 | 从系统设置强行停止应用后重开 | 不自动续跑；未结束的任务不保证生成最终摘要 |

撤权命令（替换实际设备序列号，测试结束后使用 allow 恢复）：

```bash
adb -s <device> shell appops set com.langqi.fakegps android:mock_location ignore
adb -s <device> shell appops set com.langqi.fakegps android:mock_location allow
```

普通定位运行时权限被系统撤销时，系统可能直接终止应用进程；这种情况下遵循上表的进程终止边界。

## 覆盖升级

1. 准备由同一证书签名的旧 APK 与新 APK，新 APK 的 `versionCode` 更高。
2. 安装旧版，选择非首条内置路线，设置配速、圈数和间隔；导入一条自定义路线并完成一次任务。
3. 使用 `adb install -r <新APK>` 覆盖安装，不卸载、不清除数据。
4. 确认路线名称、参数、自定义路线与最近结果保持一致，再开始一次运行。
5. 从 1.0 版升级时，额外检查 `默认路径` 与 `大学路 6` 等非首条路线的迁移。

1.0 版迁移表来自提交 `8a42c1e` 的 Debug / Release 资源表。其他自行改动资源表的旧构建
无法仅凭数字 ID 可靠判断原路线，未知 ID 会回退到默认选择，需手动确认。
签名不同的 APK 不能执行此覆盖升级流程；Debug → 新 Release 首次迁移请保留原始 KML，卸载旧版后重新导入。
